# B站 视频读取 · 分享卡片

一个扩展包吃下 B 站三件事：**搜视频发卡片**、**扒字幕**、**按画面变动抽帧拼长图**。

- 纯 cookie，**不用开浏览器**，不装 puppeteer/playwright
- 抓取默认丢**后台**，跑完自己回来喊你，不堵着对话
- **单飞锁**：同一时间只抓一个，后来的最多排一个
- 产出统一落在包内 `data/`，卸载包就一起清干净

---

## 快速开始（三步）

1. 面板 → 扩展包 → 装本包 → 重启插件
2. （可选但强烈建议）把 B 站 **SESSDATA** 填进设置页 → 才能拿 AI 字幕
3. 群里发 `/扒b站 BV1xxxxxxxxx`，或对 AI 说「把这个视频的字幕扒下来」

> SESSDATA 是**每个人自己的**，包里不带任何 cookie。不填也能抓：抽帧走公开流，
> 字幕只拿得到 UP 主自己传的那种（AI 字幕必须登录）。

## 一、SESSDATA 怎么拿（30 秒）

1. 电脑 Chrome 打开 <https://www.bilibili.com>，确认**已登录**
2. `F12` → 顶部选 **Application**（应用）
3. 左侧 **Cookies** → `https://www.bilibili.com`
4. 找名字叫 **SESSDATA** 的那行，双击 Value 全选复制（很长，常带 `%2C`）
5. 填进设置页，或群里发 `/扒b站 cookie <粘贴值>`

优先级：设置页填的 > `/扒b站 cookie` 存的 > 环境变量 `BILI_SESSDATA`。

过期了重取一次即可，不清理就一直有效。

## 二、斜杠命令

| 命令 | 作用 |
|---|---|
| `/扒b站 BV1xxxxxxxxx` | 后台抓：字幕 + 简介 + 智能抽帧长图 |
| `/扒b站 BV1xxxxxxxxx 16` | 一张长图拼 16 帧 |
| `/扒b站 BV1xxxxxxxxx 字幕` | 只抓字幕，不抽帧 |
| `/扒b站 BV1xxxxxxxxx 匀速` | 老式匀速抽帧（默认 10 秒一张） |
| `/扒b站 BV1xxxxxxxxx 等待` | 不后台，当场等结果（短视频想立刻看） |
| `/扒b站 https://b23.tv/xxxx` | 短链 / 完整链接都认 |
| 引用一条带链接的消息 + `/扒b站` | 不用打参数，自动从被引消息里抠 |
| `/扒b站 cookie <值>` | 存 SESSDATA |
| `/扒b站 目录` / `/扒b站 清理` | 看占用 / 清空产出 |

别名：`/bili`、`/bzl`。

## 三、AI 工具（模型可调）

### `bili_share` —— 搜视频发图文卡片

| 参数 | 说明 |
|---|---|
| `action` | `search` 只搜 / `share` 搜到就发卡片（默认）/ `search_user` 搜 UP 主 / `user_videos` 按 UP 找投稿 |
| `keyword` | 关键词 |
| `bvid` | 有 BV 号就直接分享 |
| `index` | 搜到多条时分享第几条 |
| `dryRun` | 只预览不发送 |

### `bili_grab` —— 字幕 + 抽帧长图

| 参数 | 默认 | 说明 |
|---|---|---|
| `bvid` | — | BV 号 / 完整链接 / b23.tv 短链 |
| `sync` | `false` | `false` 丢后台（跑完注入提醒），`true` 当场等 |
| `subtitle` | `true` | 抓字幕（md/txt/srt/json 四份） |
| `frames` | `true` | 抽帧并拼长图 |
| `frameMode` | `scene` | `scene` 按画面变动挑帧 / `interval` 匀速 |
| `perSheet` | 16 | 一张长图最多几帧（竖屏 8，上限 24） |
| `cols` | 横 2 / 竖 1 | 长图列数 |
| `cut` | 0.35 | 画面大变动阈值（0.25 敏感、0.4 平衡、0.5 只抓硬切） |
| `maxGap` | 8 | 最长多少秒必须补一帧 |
| `minGap` | 2 | 两次选帧最少隔几秒 |
| `qn` | 32 | 32=480P、64=720P、80=1080P（高清要登录） |
| `maxSeconds` | 0 | 只处理前 N 秒 |
| `action=info` / `clear` | — | 看产出占用 / 清空 |

### `bili_fetch` —— 抓取入口

给你一份「拿字幕该用哪条命令」的模板（历史包袱：早期靠 bsk 浏览器，现在用不上了，留着当速查）。

## 四、抽帧算法（为什么长这样）

**画面变动怎么判？** 用 ffmpeg 的 `scene` 指标 —— 当前帧与上一帧的「不相似度」，0 完全相同、1 完全不同。
阈值经验：`0.2` 抖动闪光全进来 / `0.3` 激进 / `0.4` 平衡 / `0.5` 只抓硬切。默认 `0.35`。

**光有阈值不够**，还要三重兜底：

1. **最长 8 秒补一帧** —— 画面不动也不至于整段漏掉；纯静止时补帧间隔自动拉长到 12 秒，免得拼一堆重复格
2. **SSIM 复核** —— 抽完的帧两两比相似度，`≥0.97` 直接丢掉（scene 只看像素差，游戏 UI 跳个数字就能误判）
3. **总量控制** —— 按视频时长分档：≤3 分钟 16 帧、≤10 分钟 40 帧、≤20 分钟 56 帧、更长 72 帧，超了等间隔降采样，保证从头到尾都覆盖

**分张与排版**

- 一屏 16 格，总图数通常 1~4 张，不会把 16 分钟的视频刷成 16 张图
- 每格左上角烧「序号 + 时间戳」，方便对着字幕找位置
- 帧间隔 < 4 秒的快节奏段落自动切 3 列（二重细分思路：快画面人眼也只记个大概）

## 五、产出长什么样

```
extension-packs/bili-share/data/
  _out/<BV号>/
    info.md              标题 / UP主 / 时长 / 发布时间 / 播放点赞投币收藏 / 简介全文
    subtitle.md          带 [秒] 时间戳的逐行稿（喂 AI 最省）
    subtitle.txt         纯文字
    subtitle.srt         标准字幕，播放器能挂
    subtitle.json        原始数据（from/to）
    frames/sheet_01.jpg  长图（fps 拼格 + 时间戳）
    frames/raw/          单帧原图
    video.m4s            视频流（下次复用，不用重下）
  _jobs/                 后台任务状态与结果
```

滚动清理：超过 24 小时或超过 15 个视频目录，自动删最旧的。也可以 `/扒b站 清理` 一把清空。

## 六、常见问题

**Q：抓不到字幕？**
A：先看有没有填 SESSDATA。填了还没有，多半是这条视频确实没字幕（不是所有视频都有 AI 字幕）。

**Q：后台任务一直没回来？**
A：看 `data/_jobs/` 里有没有 `job.json`。`job.json` 里 `pid` 那个进程还在跑就是正常的；超过 20 分钟会注入一条失败提醒。

**Q：为什么同时只抓一个？**
A：抓取要下视频流 + 跑 ffmpeg，并发会互相拖死。后来的自动排队（最多排 1 个），前面跑完自动接上。

**Q：很长的视频会不会很贵？**
A：字幕一条 3 分钟视频约 2000 token，看长图另算（每张 800~1600 token）。所以本包默认只出 1~4 张长图，而不是几十张。

**Q：视频链接后面带 `?share_source=...` 会出问题吗？**
A：不会，参数会被自动跳过；`b23.tv` 短链会跟 302 拿到真 BV 号。

## 七、依赖

- 插件版本 ≥ 1.11.17
- **ffmpeg**（抽帧必需）。Windows 默认去 `D:/newwenjianjia/videocut/ffmpeg/bin/ffmpeg.exe`，
  换机器请改 `tools/bili_grab.mjs` 顶部的 `FFMPEG` 常量，或把 `ffmpeg` 放进 PATH
- 无需 pip、无需浏览器
