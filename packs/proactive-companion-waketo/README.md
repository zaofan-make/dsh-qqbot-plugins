# proactive-companion (贴心陪伴与主动关怀扩展包)

专为 `dsh-qqbot` 打造的主动陪伴扩展包。解决机器人“你不找她她就不找你”的冷清感，让机器人在 QQ 私聊中具备适时主动关怀主人、日常冒泡分享的陪伴感。

---

## ✨ 核心特性（双路线并行架构）

### ⏰ 路线一：作息时段定时关怀 (Window Greeting)
针对关键生活与工作节奏，在特定时间段内主动发起自然问候（每个窗口当天最多触发 1 次，防止重复刷屏）：
- **早安问候**：默认 `08:30` ~ `09:30`，元气问候开启新的一天；
- **午后提神**：默认 `14:00` ~ `14:30`，午后易困时段提醒伸伸懒腰、喝口温水；
- **傍晚提醒**：默认 `18:30` ~ `19:30`，傍晚下班/放学时段关心辛苦、提醒吃好吃的；
- **晚安陪伴**：默认 `22:30` ~ `23:30`，深夜临睡提醒早点休息、祝好梦。
*注：各时段支持在 Web 设置页独立开启/关闭，并可灵活自定义具体起止时间点。*

### 💬 路线二：空闲超时主动冒泡 (Idle Poke)
- **超时触发**：当主人连续较长一段时间未在私聊发消息（**默认阈值为 3 小时**），且当前处于活跃时段时，机器人会主动戳一戳主人或分享日常。
- **独立开关**：支持在 Web 界面和指令中单独开启或关闭该机制。小时大于 0 时使用小时阈值；小时设为 **0** 时使用分钟阈值（默认 30 分钟，最少 1 分钟）。
- **巡检与诊断**：启动 15 秒后首次检查，此后每 30 秒检查。`/companion status` 显示最近检查原因和发送错误；达到空闲阈值后仍须满足冷却、免打扰和未回复保护条件。

### 🛡️ 频控与多层防骚扰退避（绝不成为垃圾消息）
1. **夜间绝对免打扰 (DND)**：默认 `23:30` ~ 次日 `08:30` 静默，不主动发送任何非紧急打扰消息。
2. **每日上限硬闸门**：默认每天最多主动关怀 `5` 次；设为 **0 表示无每日上限**，仍遵守冷却、免打扰和连续未回复保护。
3. **最小发送冷却**：默认两次主动发送之间至少间隔 `2.5` 小时；设为 **0 表示关闭发送冷却**，空闲阈值、免打扰和连续未回复保护仍然生效。
4. **智能指数退避与休眠**：
   - 若主动发了 1 次主人未回，下次触发冷却时间自动延长；
   - **连续 2 次无应答即进入休眠**，不再继续打扰，直到主人下次主动说话才重新激活。
5. **对话免打扰保护**：
   - 若主人在最近 20 分钟内才刚在说话，定时时段问候会自动避让，不生硬打断当前正在进行的对话。
6. **首次运行保护**：
   - 没有真实互动历史时不会立即发送，避免把首次安装误判为空闲超时。

### 📍 设置位置在哪里？

本扩展包内置了完整的可视配置界面，您可以通过以下方式找到并修改设置：

1. **入口一：卡片齿轮快捷直达（推荐）**
   - 进入 DSH 桌面端顶部的 **「QQ机器人扩展」** 页面；
   - 切换到 **【扩展包】** 标签页，找到 **「主动陪伴与私聊关怀」** 卡片。旁边的设置中心也可以；
   - 在卡片底部的「事件钩子」一栏中，直接点击 **`companion-daemon` 旁边的小齿轮 ⚙️ 图标**，即可直接弹出图形化配置表单。
2. **入口二：QQ 聊天内指令配置**
   - 在 QQ 私聊或群聊中直接发送 `/companion` 可查看实时状态；
   - 发送 `/companion set idle 3` 或 `/companion set max 5` 等命令随时随地快速微调。

## ⚙️ 配置与使用方式

### 1. Web 界面设置项说明
打开设置弹窗后，支持配置以下选项：
- **全局控制**：
  - `启用主动关怀总开关` (bool)：总开关，关闭后停止一切主动问候与冒泡；
  - `主人 OpenID` (string)：接收关怀的目标私聊 OpenID。建议明确填写；留空时仅回退到宿主提供的主人列表，不会从任意最近 C2C 会话中猜测目标；
  - `称呼` (string，默认“主人”)：主动问候中使用的称呼，可自定义；
  - `每天最大关怀次数` (number，默认 5 次)：路线一与路线二共享的每日总配额，0 表示无每日上限；
  - `两次关怀最小间隔(小时)` (number，默认 2.5 小时)：防刷屏最小冷却时间，0 表示关闭冷却；
  - `免打扰开始/结束时间` (string，默认 23:30 ~ 08:30)：夜间绝对静默时段。
- **【路线一】作息时段关怀**：
  - `开启作息时段关怀` (bool)：时段关怀总开关；
  - `早安问候` 开关及起止时间（默认开启，08:30 ~ 09:30）；
  - `午后提神` 开关及起止时间（默认关闭，14:00 ~ 14:30，可按需开启）；
  - `傍晚提醒` 开关及起止时间（默认关闭，18:30 ~ 19:30，可按需开启）；
  - `晚安陪伴` 开关及起止时间（默认开启，22:30 ~ 23:30）。
- **【路线二】空闲超时冒泡**：
  - `开启空闲超时主动冒泡` (bool)：超时冒泡总开关；
  - `空闲超时阈值(小时)` (number，默认 3 小时)：大于 0 使用小时；设为 0 使用分钟阈值。
   - `空闲超时阈值(分钟)` (number，默认 30 分钟)：小时为 0 时生效，最少 1 分钟。

### 2. QQ 内斜杠命令
在 QQ 私聊或群聊中发送：
- `/companion` 或 `/companion status`：查看完整的双路线运行面板、各时段今日问候状态、当前已空闲时长与频控统计；
- `/companion on` / `/companion off`：开启或暂停总开关；
- `/companion test`：按主人权限、目标 OpenID、每日额度和冷却条件，立即演练一次关怀问候；
- `/companion set idle 3`：将空闲超时阈值改为 3 小时（或其他数值）；
- `/companion set minutes 1`：切换到分钟模式，空闲满 1 分钟触发；
- `/companion set max 0`：取消每日次数上限；
- `/companion set window on/off`：单独开启/关闭时段关怀路线；
- `/companion set poke on/off`：单独开启/关闭空闲超时冒泡路线；
- `/companion set max 4`：设置每天最多关怀次数；
- `/companion set dnd 23:30 08:30`：修改夜间免打扰时段。

### 3. 自然语言与 LLM 工具 (companion_manage)
聊天过程中，你可以随时用口语告诉机器人：
- *“下午我要专注备考，今天别主动找我了”*
- *“把空闲冒泡时间改成两小时”*
机器人可自动识别并调用 `companion_manage` 工具修改策略。

该工具仅允许主人调用，支持查询状态、开关总开关、今日静默、调整空闲阈值、开关路线和立即触发测试。工具使用 `run` 入口和扁平参数 Schema。

## 📝 版本更新历史 (Changelog)

### v1.0.5 (2026-10-25)
- **零冷却支持**：两次关怀最小间隔允许设置为 0，关闭发送冷却；面板和 `/companion set interval 0` 使用相同规则。
- **空闲巡检修复**：兼容宿主真实历史字段，跨日查找互动；使用明确目标的统一发送通道，兼容启动钩子缺少 API 凭据的情况，失败不占用额度；
- **分钟模式与不限次数**：小时为 0 时使用分钟阈值；每日最大次数为 0 时无每日上限；今日静音单独记录；
- **可观测性与回归**：每 30 秒巡检，状态显示阻挡原因和发送错误，增加真实巡检回调与模拟传输回归。

### v1.0.4 (2026-10-25)
- **配置与状态统一**：统一面板、命令、工具和守护进程使用的 ext-config 路径与配置优先级，修复面板配置读取不到、状态与实际目标不一致的问题；
- **命令参数修复**：改用 dsh 提供的 `ctx.command.raw` 解析子命令，修复 `/companion test`、`set` 等命令始终返回状态页的问题；
- **工具契约修复**：将 `companion_manage` 入口统一为 `run`，并将参数 Schema 改为扁平结构，修复工具无法加载或参数错位的问题；
- **目标与权限安全**：增加主人权限校验，禁止从任意最近 C2C 会话猜测收件人；缺少可信目标时跳过主动发送；
- **频控与生命周期修复**：统一每日额度、冷却、连续未回复和窗口状态记账，修复首次启动误触发、重复定时器、测试触发绕过频控等问题；
- **称呼可配置**：移除硬编码昵称，新增 `displayName` 配置，默认称呼为“主人”；
- **写入稳定性**：配置使用随机临时文件进行原子替换，降低并发写入和 Windows 文件冲突风险。

### v1.0.3 (2026-10-24)
- **智能 OpenID 自动识别与防隐私泄露**：
  - 设置面板中的 `targetOpenid`（主人 OpenID）变更为非必填项；
  - 移除硬编码私人 OpenID，避免用户敏感 ID 泄露。
- **历史记录路径解析与空闲判断 Bug 修复**：
  - 修正陪伴守护进程查找私聊历史记录时使用 `process.cwd()` 导致无法定位真实存储路径的问题，优先从 `env.dataRoot` 精准索引；
  - 修复首次无历史记录时错误判断空闲状态的问题。

### v1.0.2 (2026-10-24)
- **时段关怀默认开关优化**：路线一中默认仅开启【早安问候 (08:30-09:30)】与【晚安陪伴 (22:30-23:30)】，将【午后提神】与【傍晚提醒】设为默认关闭；
- **双路线配额合理化调整**：明确每日最大关怀次数为路线一与路线二共享的全局总额度，默认单日总上限调整为 **5 次**。

## 本地测试

在扩展包目录执行：
```powershell
node tests/smoke.mjs
node tests/idle-regression.mjs
```
测试使用临时数据根、模拟发送和拦截的 fetch，不会发送真实 QQ 消息。回归直接运行生产巡检回调，覆盖分钟阈值、零上限、冷却、今日静音、未回复退避、跨日历史及发送失败。它不能替代真实 QQ 权限与投递验证。

快速实测：安装新版后设小时为 0、分钟为 1，每日上限为 0；确认当前不在免打扰时段且无发送冷却，再发一条私聊后停止互动，约 1 分钟加至多 30 秒巡检延迟后观察。若已有主动发送记录，最小间隔仍然生效；可用 `/companion status` 查看最近检查原因。连续两次未回复仍会休眠，0 仅取消每日次数限制。
