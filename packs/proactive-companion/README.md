# proactive-companion (贴心陪伴与主动关怀扩展包)

专为 `dsh-qqbot` 打造的主动陪伴扩展包。解决机器人“你不找她她就不找你”的冷清感，让机器人在 QQ 私聊中具备适时主动关怀主人、日常冒泡分享的陪伴感。

---

## ✨ 核心特性（双路线并行架构）

### ⏰ 路线一：作息时段定时关怀 (Window Greeting)
针对关键生活与工作节奏，在特定时间段内主动发起自然问候（每个窗口当天最多触发 1 次，防止重复刷屏）：
- **早安问候**：默认 `08:30` ~ `09:30`，元气问候开启新的一天；
- **午后提神**：默认 `14:00` ~ `14:30`，午后易困时段提醒伸伸懒腰、喝口温水；
- **傍晚提醒**：默认 `18:30` ~ `19:30`，傍晚下班/放学时段关心辛苦、提醒吃好吃的；
- **晚安陪伴**：默认 `22:30` ~ `23:30`，深夜临睡提醒早点休息、祝好梦。
*注：各时段支持在 Web 设置页独立开启/关闭，并可灵活自定义具体起止时间点。*

### 💬 路线二：空闲超时主动冒泡 (Idle Poke)
- **超时触发**：当主人连续较长一段时间未在私聊发消息（**默认阈值为 3 小时**），且当前处于活跃时段时，机器人会主动戳一戳主人或分享日常。
- **独立开关**：支持在 Web 界面和指令中单独开启或关闭该机制。小时大于 0 时使用小时阈值；小时设为 **0** 时使用分钟阈值（默认 30 分钟，最少 1 分钟）。
- **巡检与诊断**：启动 15 秒后首次检查，此后每 30 秒检查。`/companion status` 显示最近检查原因和发送错误；达到空闲阈值后仍须满足冷却、免打扰和未回复保护条件。

### 🛡️ 频控与多层防骚扰退避（绝不成为垃圾消息）
1. **夜间绝对免打扰 (DND)**：默认 `23:30` ~ 次日 `08:30` 静默，不主动发送任何非紧急打扰消息。
2. **每日触发上限**：默认每天最多接纳主动关怀 `5` 次；设为 **0 表示无每日上限**，仍遵守冷却、免打扰和连续未回复保护。
3. **最小发送冷却**：默认两次主动发送之间至少间隔 `2.5` 小时；设为 **0 表示关闭发送冷却**，空闲阈值、免打扰和连续未回复保护仍然生效。
4. **智能指数退避与休眠**：
   - 若主动发了 1 次主人未回，下次触发冷却时间自动延长；
   - **连续 2 次无应答即进入休眠**，不再继续打扰，直到主人下次主动说话才重新激活。
5. **对话免打扰保护**：
   - 若主人在最近 20 分钟内才刚在说话，定时时段问候会自动避让，不生硬打断当前正在进行的对话。
6. **首次运行保护**：
   - 空闲路线没有真实互动历史时不会立即触发，避免把首次安装误判为空闲超时。作息路线按时间窗口判断，但同样要求目标原私聊会话已存在。

## ⚙️ 配置与使用方式

### 1. Web 界面设置项说明
打开设置弹窗后，支持配置以下选项：
- **全局控制**：
  - `启用主动关怀总开关` (bool)：总开关，关闭后停止一切主动问候与冒泡；
  - `主人 OpenID` (string)：接收关怀的目标私聊 OpenID。可在私聊中直接发送 `/openid` 一键自动获取并填入；
  - `每天最大关怀次数` (number，默认 5 次)：路线一与路线二共享的每日总配额，0 表示无每日上限；
  - `连续无应答休眠上限` (number，默认 3 次)：连续主动找主人未收到回复时的挂起保护上限（双路线共享），达到后暂停主动关怀；设为 0 表示不休眠；
  - `两次关怀最小间隔(小时)` (number，默认 2.5 小时)：防刷屏最小冷却时间，0 表示关闭冷却；
  - `免打扰开始/结束时间` (string，默认 23:30 ~ 08:30)：夜间绝对静默时段。
- **【路线一】作息时段关怀**：
  - `开启作息时段关怀` (bool)：时段关怀总开关；
  - `早安问候` 开关及起止时间（默认开启，08:30 ~ 09:30）；
  - `午后提神` 开关及起止时间（默认关闭，14:00 ~ 14:30，可按需开启）；
  - `傍晚提醒` 开关及起止时间（默认关闭，18:30 ~ 19:30，可按需开启）；
  - `晚安陪伴` 开关及起止时间（默认开启，22:30 ~ 23:30）。
- **【路线二】空闲超时冒泡**：
  - `开启空闲超时主动冒泡` (bool)：超时冒泡总开关；
  - `空闲超时阈值(小时)` (number，默认 3 小时)：大于 0 使用小时；设为 0 使用分钟阈值。
  - `空闲超时阈值(分钟)` (number，默认 30 分钟)：小时为 0 时生效，最少 1 分钟。

### 💡 常见疑问：如何配置 OpenID？不配置 OpenID 行不行？

#### ①. 如何快速配置 OpenID？
- **最简方式（强烈推荐）**：直接在与机器人的 **QQ 私聊** 中发送一条 `/openid`（或 `/whoami`）。扩展会自动提取当前私聊的 OpenID 并直接填入配置，完全不需要手动去翻看或复制粘贴长字符串！
- **手动设置**：
  - 在 DSH 扩展设置面板中的「主人 OpenID」直接粘贴；
  - 或在聊天中发送 `/companion set id <你的OpenID>`。

#### ②. 不配置 OpenID 行不行？
- **可以，但有前提**：如果宿主机器人（dsh-qqbot 主插件）已经在全局配置的 `owners`（主人列表）中填了你的 OpenID，本扩展会自动回退识别宿主主人作为目标，此时此处留空也能正常工作。
- **为什么不建议完全不配？**：如果宿主没有配置 `owners`，且本插件也留空，插件将出于**严格的隐私安全保护**进入无目标静默状态（`missing_target`）。插件绝不会从最近聊天的路人或群友私聊中“盲猜”目标，防止把专属的主动问候发给无关陌生人。因此在私聊里发一句 `/openid` 绑定一下是最稳妥省心的做法。

### 2. QQ 内斜杠命令
在 QQ 私聊或群聊中发送：
- `/openid`（或 `/whoami`）：**在私聊中一键获取当前会话的 OpenID 并自动填入设置面板**，省去手动查找配置的步骤；
- `/companion` 或 `/companion status`：查看完整的双路线运行面板、各时段今日问候状态、当前已空闲时长与频控统计；
- `/companion on` / `/companion off`：开启或暂停总开关；
- `/companion test`：立即请求原私聊会话生成关怀，跳过空闲阈值和作息窗口；仍遵守总开关、今日静音、夜间免打扰、每日额度、冷却和未回复保护；
- `/companion set id <openid>`：手动设置目标主人 OpenID；
- `/companion set unanswered 3`：设置连续无应答休眠上限（0 为不休眠，双路线共享）；
- `/companion set idle 3`：将空闲超时阈值改为 3 小时（或其他数值）；
- `/companion set minutes 1`：切换到分钟模式，空闲满 1 分钟触发；
- `/companion set max 0`：取消每日次数上限；
- `/companion set window on/off`：单独开启/关闭时段关怀路线；
- `/companion set poke on/off`：单独开启/关闭空闲超时冒泡路线；
- `/companion set max 4`：设置每天最多关怀次数；
- `/companion set dnd 23:30 08:30`：修改夜间免打扰时段。

### 3. 自然语言与 LLM 工具 (companion_manage)
聊天过程中，你可以随时用口语告诉机器人：
- *“下午我要专注备考，今天别主动找我了”*
- *“把空闲冒泡时间改成两小时”*
机器人可自动识别并调用 `companion_manage` 工具修改策略。

该工具仅允许主人调用，支持查询状态、开关总开关、今日静默、调整空闲阈值、开关路线和立即触发测试。工具使用 `run` 入口和扁平参数 Schema。

### 💡 注意：连续无应答休眠熔断保护（为什么发了几次就不发了？）

很多用户可能会好奇：*“为什么机器人主动找我发了 3 次消息，见我没回，之后就不再发了？”*

这是扩展包中非常核心且体贴的 **「防打扰熔断与真人退避保护机制」**：

1. **设计初衷（防刷屏与情商退避）**：
   - 避免在主人开会、专注学习、睡觉或外出有急事时，机器人像复读机一样不依不饶地反复震动弹窗造成骚扰；
   - 贴近真实人类伴侣或好友的交往心理：主动搭话了 1~2 次见你一直没回，下一次的主动间隔会自动延长为 **1.6 倍**；当连续搭话达到设定的上限（默认 **3 次**）后，便会识趣地**暂停主动推送、静静等待你空闲**。
2. **两条路线完全共享计数**：
   - **【路线一】作息问候**（早安/午后/傍晚/晚安）与 **【路线二】空闲超时冒泡** **完全共享该连续未回复计数**！
   - 例如：如果早上发了早安问候未收到回复、下午空闲冒泡仍未回复、傍晚又提醒了一次依然未回复（累计达到 3 次），则当晚的晚安关怀将自动熔断挂起，不会继续打扰。
3. **秒级唤醒与自动解冻**：
   - **极其轻量，回复一句即可解冻**：只要你在 QQ 私聊中**回复任意一句话**（哪怕是一个字、一个表情包，或者发送一条指令），后台的无应答计数会**瞬间归零**，双路线主动机制立刻恢复正常轮询！
4. **如何调整或关闭休眠限制？**
   - **调大次数**：在设置面板中将「连续无应答休眠上限」由 3 改为 5 或更大；
   - **彻底不休眠**：将「连续无应答休眠上限」设为 `0`，即可完全关闭该保护，无论是否回复都会按时段和空闲节奏主动冒泡；
   - **指令快速修改**：私聊发送 `/companion set unanswered 5` 或 `/companion set unanswered 0`。

## 📝 版本更新历史 (Changelog)

### v1.1.1 (2026-10-29)
- **通道工具与上下文三连自愈（彻底解决 `list_stickers` 等工具报 UNKNOWN_TOOL）**：
  - 根因：宿主 `@zaofan/dsh-qqbot` (2026-10-28) 将表情包、媒体发送等内置通道工具改为按 QQ 会话作用域注册。普通用户入站消息走 `inbound.js` 会先触发工具与上下文自愈；而主动关怀从闲置恢复会话时绕过了 `inbound.js`，导致 DSH 引擎未执行 setup 钩子，恢复出的会话缺失 `list_stickers`、`send_media` 等通道工具，模型尝试发表情包即抛出 `ToolNotFoundError: UNKNOWN_TOOL`；

## 本地测试

在扩展包目录执行：
```powershell
node tests/smoke.mjs
node tests/idle-regression.mjs
node tests/session-regression.mjs
```
测试使用临时数据根和独立的假宿主注册表，旧传输测试拦截 fetch，不会发送真实 QQ 消息。回归直接运行生产巡检回调，覆盖原会话路由、实例隔离、提示内容、并发额度、分钟阈值、零上限、冷却、静音、未回复退避、跨日历史和唤醒失败。它验证路由与调度逻辑，不验证真实模型的人设表现、图片选择或 QQ 最终投递。

快速实测：安装新版后设小时为 0、分钟为 1，每日上限为 0；确认当前不在免打扰时段且无发送冷却，再发一条私聊后停止互动，约 1 分钟加至多 30 秒巡检延迟后观察。若已有主动发送记录，最小间隔仍然生效；可用 `/companion status` 查看最近检查原因。连续两次未回复仍会休眠，0 仅取消每日次数限制。


## 宿主兼容与实测

v1.0.6 对接本机检查过的 dsh-qqbot **1.10.38** 的 `dist/features/session-registry.js` 和 `SessionManager.injectToPeer`。这是宿主内部兼容接口，并非稳定公开契约；其他版本需验证。扩展从运行时 DSH_PROFILE_DIR 或 Node 包解析定位宿主，无本机用户名或安装绝对路径硬编码。若模块无法定位或注册表无法复用，会安全失败并显示 `HOST_BRIDGE_UNAVAILABLE`。

安装或更新后重启机器人，先与机器人正常私聊一轮，建立目标原会话；再在允许触发的时段执行 `/companion test`。提示已接纳后，观察 QQ 是否收到结合刚才话题的自然回复；图不一定每次出现，必须原会话已启用图库工具和媒体能力。只有收到 QQ 回复才算完成端到端验证。宿主的 `silent` / `nothink` 模式会禁止出站；`passive` 仍受被动回复的消息时效约束。需要主动关怀时，请使用宿主支持主动出站的模式（例如 `adaptive`），并确认机器人具有对应发送权限。

诊断：`SESSION_NOT_READY` 表示目标原私聊会话未建立或已被回收，先正常私聊一轮；`AMBIGUOUS_INSTANCE` 表示同一数据根存在多个匹配实例，检查多账号数据根配置；`WAKE_REJECTED` 表示宿主未接纳；`queued` 表示已交给模型处理，不保证模型执行或 QQ 投递成功。失败时不会回退到固定话术，也不读取或改写其他会话、定时任务文件。
